# Leica M8 firmware project

Personal reverse-engineering project on the author's own Leica M8 (running patched 2.014).
Goal 1: make the service-mode "JPG fine+RAW" (14-bit) setting persist — DONE, patched 2.014 flashed and
working on the camera (2026-10-19).
Goal 2: have the camera write 14-bit DNG directly — DONE (2026-10-20): Option 2 (`dng`, `55264b11…`,
BlackLevel per ISO): JPG fine+RAW writes JPG + 14-bit DNG content named `.RAW`; Lightroom opens it as
is. `.DNG` names (old stage 5) broke in-camera review, so the files stay `.RAW`.

**Builds = option + add-ons (since 2026-11-03; no more stage numbers).** Pieces, each camera-tested
(`m8_dngpatch.TESTED_PIECES`, the flashed build and date):
- `raw-menu` (Option 1, RAW patch, `f6589c41…`, 2026-10-19); `dng` (Option 2, `55264b11…`, 2026-10-21);
- `--info`: INFO in shooting mode shows Camera stats (`32e6854e…`, 2026-10-23);
- `--profiles`: Camera stats + picture-profile picker, UP → `\PROFILES\*.LUT`, SET loads until
  power-off (`d7a17ef2…`, 2026-10-27);
- `--dial-ev`: rear dial sets exposure compensation (Leica's dormant ⅓ EV step, shown on the rear
  screen, closes after 2 s or any key; `1254b743…` = `dng --profiles --dial-ev`, 2026-11-02).
- `--meta` (with `dng`): per-shot white balance + Leica MakerNote; code in `writejpgipp`
  (0x26D98), tables in `ldimg`. First version flashed 2026-11-05: MakerNote OK, WB not (the neutral
  isn't in the job yet at the RAW). Now with piece `meta fetch` (0x3CB98: a RAW asks for the neutral
  first, as a DNG does): **camera-tested 2026-11-05** as `dng --meta --profiles --dial-ev`
  (`4359b04b…`, WB + MakerNote == the JPG; `TESTED_PIECES['meta']`). `m8patch.py dng … --meta`
  offers the 6 `META_BUILDS` (v0.7.0; .BIA long exposure camera-tested 2026-11-06).
12 + 6 builds (`m8_dngpatch.BUILDS` + `META_BUILDS`); **owner's decision 2026-11-02: a build may ship when every piece is
camera-tested**, pieces byte-identical to those builds and regions disjoint (`tools/m8_combotest.py`).
A new or changed piece needs its own camera test. **Author's camera: `dng --profiles --dial-ev`
(`1254b743…`); roll back to `dng --profiles` (`d7a17ef2…`).**
Owner's decisions: no histogram / image screens (PLAY has one); INFO = Camera stats (an M10-style
overview was built and rejected 2026-11-03); stock tone curves stay the default (a built-in MODERN
curve, old stage 12, was flashed and rolled back 2026-10-27).
History: builds used to be numbered stages. Diagnostic / one-off builds keep their numbers
(`m8_dngpatch.HISTORY`, `--stage N`: 1 canary, 2 idle, 3 dump, 5 .DNG names, 6 INFO → Body Debug Data,
7 histogram screens, 11 `\PROFILE.LUT` test, 12 MODERN default); old numbers of builds are aliases
(`OLD_NUMBERS`: 4 dng, 8 dng --info, 10 raw-menu --info, 13 dng --profiles, 14 raw-menu --profiles,
15-20 the --dial-ev builds) so FINDINGS and old hashes still resolve. Don't add new numbers.

Read `docs/FINDINGS.md` first — it holds every address, offset, hash and conclusion so far.
For Goal 2, read `docs/DNG_PLAN.md` — the agreed approach, tag list, constraints, firmware leads and step-by-step work plan.

## Layout
- `firmware/stock/` — untouched Leica .upd files. Never modify; verify SHA-256 against FINDINGS.
- `firmware/patched/` — generated by `tools/m8_rawpatch.py`. Regenerate rather than hand-edit.
- `m8patch.py` — user front end: `python3 m8patch.py raw-menu|dng stock.upd [--meta] [--info|--profiles] [--dial-ev] [--out-dir DIR]`
  → `build/` (builds via `m8_dngpatch.build_file(stock, option, screen, dial, meta)`; `--meta` dng only).
  Writes only results matching `TESTED` (18 hashes, each "exact" or "pieces" camera-tested; `PENDING` =
  built but refused until camera-tested); never overwrites. `m8patch.py profiles stock.upd X.ncp|dir|modern …
  [--base srgb|modern|leica]` → `build/PROFILES/NAME.LUT` + `LEICA.LUT` (via tools/m8_profile.py).
- `tools/split_upd.py` — `python3 tools/split_upd.py firmware/stock/m8-2_014.upd work/split-2.014`
- `tools/armtools.py` — Capstone helpers (dis, xrefs, callers); defaults to `work/split-2.014/PXA.bin`
- `tools/m8_rawpatch.py` — `python3 tools/m8_rawpatch.py firmware/stock/m8-2_014.upd firmware/patched/m8-2_014.upd`
- `tools/m8_emutest.py` — Unicorn test of the RAW patch (~1 s): `work/venv/bin/python tools/m8_emutest.py [-v]`
- `tools/m8_dngpatch.py` — builds from pieces, with region / original-byte checks and disassembly of every change:
  `work/venv/bin/python tools/m8_dngpatch.py firmware/stock/m8-2_014.upd OUT.upd raw-menu|dng [--info|--profiles] [--dial-ev]`
  (or `--stage N` for a HISTORY / old number)
- `tools/m8_infotest.py` — INFO builds (old numbers 6-8, 10, 11, 13, 14) vs `dng` / Option 1: real key handler, all keys and GUI states (~10 s):
  `work/venv/bin/python tools/m8_infotest.py [-v]`
- `tools/m8_inforender.py` — INFO screens (old number 8 = `dng --info`; `--stage 7`/`10`/`11`/`13`/`14`): runs the real GUI paint code, writes PNGs + checks (~2 s):
  `work/venv/bin/python tools/m8_inforender.py [image.JPG] [--stage 7|8|10] [--out DIR] [-v]`
- `tools/asm/` — assembly sources of the new code (`m8_header.s`, `m8_dnghook.s`, `m8_dngmeta.s`, `m8_info.s`, `m8_infoscreens.s`, `m8_infostats.s`, `m8_infoprofile.s`, `m8_infopicker.s`, `m8_infoev.s`); `tools/m8_asm.py X.s`
  assembles one and prints bytes + SHA-256 (the patch script carries the frozen bytes).
- `tools/m8_combotest.py` — all 18 m8patch builds: hash, == build_file, each piece byte-identical to its
  camera-tested build, changes only in the pieces' regions (~5 s): `work/venv/bin/python tools/m8_combotest.py`
- `tools/m8_evtest.py` — every `--dial-ev` build vs the same build without it: key handler (all keys, 12 GUI states),
  page keys, timer, Leica's EV step run for real, paint PNGs `work/ev-*.png` (~30 s): `work/venv/bin/python tools/m8_evtest.py [-v]`
- `tools/m8_savetest.py` — emulated RAW save path, tests the 18 builds + diagnostic builds 1/2/3/5 against the camera
  samples (M4 Max: ~25 min all, ~2.5 min one build):
  `work/venv/bin/python tools/m8_savetest.py [--build dng --profiles --dial-ev | --stage N] [--quick] [-v]`
- `tools/m8_reclaim.py` — ranks debug-command handlers as reclaimable space: `work/venv/bin/python tools/m8_reclaim.py`
- `tools/m8_font.py` — decodes the GUI fonts, renders text or a glyph sheet (read-only):
  `work/venv/bin/python tools/m8_font.py work/split-2.014/GUI_FONT1.bin text "ISO 640" out.png`
- `tools/m8_profile.py` — tone curve → `build/profiles/NAME.LUT` (stock GAMMA with 15 new curves: one
  tone, Leica's 5 Contrast steps, encoded for Adobe RGB / sRGB / ECI RGB; contains Leica data, private).
  Source: Nikon .NCP or "x,y" points (on `--base srgb|modern|leica`), or built-in `modern`, `moderndr`,
  `srgb`, `leica`, `stock` (exact copy). `--preview X.RAW` renders it from your RAW (FINDINGS "JPG tone curves"):
  `work/venv/bin/python tools/m8_profile.py firmware/stock/m8-2_014.upd X.NCP|modern [--preview X.RAW]`
- `tools/ncp.py` — Nikon Picture Control (.NCP) reader (no M8 knowledge).
- `tools/m8_curvesim.py` — renders .LUT curves from a RAW + its camera JPG (fits the camera's colour from
  the JPG; checks itself against the JPG, ~2 levels): `… m8_curvesim.py STOCK.upd X.RAW A.LUT [B.LUT]` → `build/curves/`
- `tools/m8_curvetest.py` — curve checks (~1 s): Leica rebuild, valid tables, stage 12 vs 11 only in GAMMA curves.
- `tools/ghidra/` — headless Ghidra scripts (M8Pre seed/options, M8Xrefs refs into ranges, M8Coverage).
  Ghidra 12.1.4 + Temurin JDK 21 unpacked in `work/ghidra/` (re-download if work/ is wiped). Run:
  `JAVA_HOME=work/ghidra/jdk-21.0.12.1+1/Contents/Home work/ghidra/ghidra_12.1.4_PUBLIC/support/analyzeHeadless work/ghidra/proj m8 -import work/split-2.014/PXA.bin -overwrite -loader BinaryLoader -loader-baseAddr 0x20000 -processor ARM:LE:32:v5t -scriptPath tools/ghidra -preScript M8Pre.java -postScript M8Xrefs.java name:lo:hi ...`
- `tools/m8_wrapdng.py` — desktop prototype of the in-camera RAW→DNG wrap: `python3 tools/m8_wrapdng.py sampleraws/X.RAW` [--meta]
- `tools/m8_metacheck.py` — `--meta` camera files: DNG MakerNote / AsShotNeutral vs the JPG, job dump:
  `python3 tools/m8_metacheck.py fromcameraimports/L*.RAW`
- `fromcameraimports/` — staging area for files copied off the camera card (test shots of each build). Keep.
- `luttests/` — camera JPGs of the tone-curve tests (stage 11). Keep.
- `sampleraws/` — camera samples (RAW, JPG, lens-cap frames) and DNGs generated from them. Keep.
- `work/` — scratch output (split lumps etc.), safe to delete.
- Sibling repo `../m8raw2dng2` — botrx555's RAW→DNG converter; `docs/PROCESSING.md` documents the RAW format.

## Rules
- Safety first: never touch RedBoot, FSL, M16C, FPGA, or PXA boot/update paths.
- PXA image cannot grow (.bss starts at image end 0xF1BB0). New code goes in reclaimed space.
- Every patch: minimal, verified by disassembly and a byte diff against stock, documented in FINDINGS.
- New code must target ARMv5TE ARM mode (XScale), no VFP/Thumb-2.
- DNG work (details and reasons: `docs/DNG_PLAN.md` §6):
  - Hook only the JPG fine+RAW save path; JPG / DNG / DNG+JPG modes stay stock (they are the kill switch).
  - New code never writes flash or EEPROM and never calls settings-save, flash or update routines.
    It only writes inside the image DMA buffer (bounds-checked in the code; skip the write if out of
    range) and its own stack; the emulator test fails on any other write.
  - Each build may differ from Option 1 only in its pieces' declared regions; checked automatically.
    New features are new pieces (flags), never new stage numbers.
  - New code stays out of startup. Before each flash, confirm the boot/update code is byte-identical
    and unreachable from the changed regions (done for stage 4, FINDINGS "Staged DNG builds").
    Stage 2 (hook off, idle test) is optional since 2026-10-20 (owner's decision): its reclaimed
    space is byte-identical to stages 4-5, so it adds diagnosis, not recoverability.
  - After any anomaly on a test build: pull the battery first — not the power switch, not the card
    (power-state changes and card insert/remove save settings to EEPROM; a battery pull saves nothing).
  - Before any new flash: rollback drill done once (patched → stock → patched), full battery,
    scratch card for shooting, separate recovery card holding only the stock .upd.
- INFO / GUI work (stage 6+, FINDINGS "GUI"): same rules as DNG work, plus
  - Hook only the application key handler's INFO case outside service mode (0x44F68); service mode
    and the `lensinfo` case stay stock. New code runs only when INFO is pressed, never at startup.
  - New code may call only existing GUI routines with the arguments the firmware itself uses for the
    same page (drawing: fill / line / text routines, FINDINGS "GUI"), and may write only: the GUI flag
    bytes the firmware's own path writes (app+0x2548F, camInfoMenu+0x99), the borrowed dialog's
    method-table pointer (restored on close), the framebuffer, and its stack. Body link: only
    command 0x33 (debug data, a read) via 0x3E238. `tools/m8_infotest.py` (key path) and
    `tools/m8_inforender.py` (paint) fail on any other call or write.
  - Never open other service pages (Production Test, EEPROM Check, Hardware ID's, …) from new code.
  - Stage 11 only (tone-curve test, owner's OK 2026-10-23; FINDINGS "JPG tone curves"): UP on the
    Camera stats screen may also take the shared file buffer without waiting (0x20F18; busy -> do
    nothing) and release it (0x20F64), read one card file `\PROFILE.LUT` with the emFile calls
    open/size/read/close (0xA6428 / 0xA4F6C / 0xA6A84 / 0xA6498), and send it to the Blackfin as
    LUT 1 (GAMMA) with 0x906C4 -- only if it is 31,760 bytes with the stock GAMMA header. Never
    write, rename or delete card files; never call the update / LUT-boot routines (0x23104,
    0x23BC4, 0x22004 …). Test curves must rise steadily (no inverted curves).
  - Stage 13 (picker) may in addition read the `\PROFILES` directory with the emFile calls OpenDir /
    ReadDir / GetName / GetAttr / GetSize / CloseDir (0xA479C / 0xA4804 / 0xA4898 / 0xA4864 / 0xA48D8 /
    0xA47D0; always closed), and keep its state in 16 bytes at 0x1531FC (the `ldimg` debug command's
    filename buffer, .bss, zero at every start-up) — no other new writes. Loads only files of 31,760 bytes
    with the stock GAMMA header, as stage 11.
  - Dial EV (stages 15-18, owner's OK 2026-10-31): new code lives in the reclaimed `setting` debug
    command (0x2C44C-0x2C9F4) and is reached only from the application key handler's switch default
    (0x44EDC) and its "`a` held" exit (0x44E9C) for the dial keys `c`/`w`, and from the GUI event
    table's handler word for event 0x271E (0xEF2B4; anything not ours goes on to 0x43B64). It may in
    addition call Leica's dial step 0x65954 (changes exposure compensation + working-profile index
    exactly as the SET menu, posts event 0x2715) and arm the dialog's own timer (0x8BD10(dialog+0x60,
    0x271E, 2000, 1, 0, 0, 0)). Never in service mode or Simple mode (settings override 5); every other
    key returns with all registers as stock. `tools/m8_evtest.py` fails on any other call or write.
  - Built-in curves (stage 12, rolled back): a build may change the LUTS lump only inside GAMMA's 15 curves
    (file span from `gamma_curves_span`), never its header/colour data, size, the LUTS directory or
    any other LUTS entry; curves rise from 0; generated bytes must match the frozen SHA-256.
- Firmware is Leica's copyright: keep private; never publish .upd files or push them to a public remote.
- Python deps: `python3 -m venv work/venv && work/venv/bin/pip install -r requirements.txt`.
- New code: assemble with Apple clang `--target=armv5te-none-eabi -march=armv5te -marm`, write it in
  assembly, freeze the resulting bytes in the patch script, verify by Capstone disassembly at the real
  address + emulator. ARMv5 rotates unaligned LDR (Unicorn doesn't model this; the harness fails any
  misaligned access instead).
